# Deploy UniCart on Render and MongoDB Atlas

Stay on Render. The blueprint is [render.yaml](../render.yaml): `campuscart-api` (Python web service) and `campuscart-web` (static site). Do not move the API or the database to Appwrite. Appwrite is not part of this project, and it would replace the FastAPI and MongoDB work.

No secret values belong in the repository. Set them in Atlas and in the Render dashboard.

## 1. MongoDB Atlas

1. Create a free cluster and a database user.
2. Allow Render's outbound addresses, or `0.0.0.0/0` if you accept that for a demo.
3. Copy the SRV connection string. The database name in the app is `campuscart` (`MONGODB_DB`).

This is the data layer behind the app. Atlas Vector Search is not wired up.

## 2. Render

1. New Blueprint, point it at this repo, and apply `render.yaml`.
2. On `campuscart-api`, set:
   - `MONGODB_URI` — the Atlas string
   - `CORS_ORIGINS` — the static site origin, for example `https://campuscart-web.onrender.com` (no trailing slash). Add a second origin, comma-separated, if you also use a .tech hostname.
   - `GEMMA_API_KEY` — Google AI Studio key, if you want listing drafts. Leave it empty and Seller Studio tells the seller to type the listing.
   - `ELEVENLABS_API_KEY` — only if dictation should fall back to ElevenLabs. Leave it empty otherwise.
   - `BACKBOARD_API_KEY` — secondary text model for listing drafts. Leave it empty and drafts stay on Gemma, or on the manual form when Gemma is also empty. `BACKBOARD_LLM_PROVIDER` defaults to `openai` and `BACKBOARD_MODEL` to `gpt-4o`.
   - `JWT_SECRET` is generated by the blueprint. Do not paste it into git.
   - `RESEND_API_KEY` — Resend API key, required before email sign-in works in production.
   - `EMAIL_FROM` — a sender Resend will accept, for example `UniCart <login@yourdomain.com>`. Until a domain is verified, Resend only delivers from `onboarding@resend.dev` to the address on the Resend account.
   - `PUBLIC_WEB_URL` — the static site origin, `https://…`, no trailing slash. Magic links in the email point here.
   - `YOUPI_API_URL` — YouPI payment API origin, no trailing slash, for example `https://pay.yourdomain.com` or the host serving port 6100.
   - `YOUPI_MERCHANT_ID` — the merchant id from the YouPI admin panel.
   - `YOUPI_WEBHOOK_SECRET` — the same value as `COIN_STORE_WEBHOOK_SECRET` on the `campuscart-youpi` service. YouPI signs callbacks with it, and UniCart sends it back as `X-Merchant-Key` when re-reading a payment. The YouPI service sends those callbacks to `https://<api>/api/payments/youpi`.
   - `ADMIN_UPI_ID` — unused for new top-ups. Left so an older environment still boots.
3. On `campuscart-web`, set `VITE_API_URL` to the API origin, for example `https://campuscart-api.onrender.com`, with no trailing slash. Rebuild the static site after changing it. The browser derives the chat socket from that URL.
4. Confirm `GET https://<api>/api/health` returns ok.
5. To load the demo stalls on that cluster, set `SEED_DEMO=1` on the API and redeploy. The process loads Kaaram & Ko, Campus Brewers, Tanuj Prints, and Potato's Makerspace after it is accepting requests, then you can set `SEED_DEMO` back to empty. From a machine that can reach Atlas, `python -m scripts.seed_campus_stores` does the same thing against a local API whose `MONGODB_URI` is that cluster. `CAMPUSCART_SEED_API` overrides the script's API base (`http://127.0.0.1:8000`).

Uploaded images and print files are stored on the API's local disk. Render's disk is ephemeral. The seeded catalogue has no uploaded photos, so the stalls survive a restart. A print file uploaded for a demo does not.

## 3. .tech domain

1. Claim the free first year at [hacktoberfest.com/my/promos](https://hacktoberfest.com/my/promos).
2. At the registrar, point the hostname at the Render static site (CNAME to the `onrender.com` host Render shows for `campuscart-web`).
3. Add that `https://` origin to `CORS_ORIGINS` and rebuild if the page is served from the custom domain.
4. Put the URL in the submission. Tick the .tech category only after that URL loads the app.

## 4. What not to claim

- Do not tick Best Use of ElevenLabs unless `ELEVENLABS_API_KEY` is set and a dictation used it.
- Do not tick Best Use of Arduino unless `edge/uno_q/` is running on an UNO Q.
- Do not tick Render or Atlas until the health check and a seeded stall both work on those services.
- Gemma stays on Google AI Studio (or a local OpenAI-compatible server via `GEMMA_BASE_URL`). Render hosts the app, which is what that category asks for.
